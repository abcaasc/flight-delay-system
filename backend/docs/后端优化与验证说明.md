### 已完成

- 修正航司筛选口径。2024 年 12 月 AA 的总览、趋势和明细均为 77,737 班，DL 均为 83,283 班。跨月接口提供实际覆盖月份和缺失月份。

- 作业心跳保存在 `sys_job_lease`。本地 SQLite 副本中 9 条失联作业已标为中断，带提交参数的作业可由管理员重试。测试中已用隔离数仓完成一次真实的作业重试。
- 预测模型使用可迁移的产物路径，模型验证页根据服务实际加载的版本判断报告是否对应当前模型。

### 表单候选模型

2024 年 10 月至 12 月每月固定种子抽取最多 50,000 班。训练日期截至 12 月 3 日，12 月 4 日至 17 日用于阈值验证，12 月 18 日至 31 日用于留出测试。下表各行都在同一批 22,541 班航班上测得，其中 11,349 班有起飞前气象观测。

| 方案 | 阈值 | 准确率 | 精确率 | 召回率 | AUC | 误报 | 漏报 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |

含气象版本处于候选阶段。少误报阈值在验证集召回率至少 40% 的条件下选出。阈值改变告警数量和漏报数量，提升模型区分能力仍依赖新增的有效输入。训练命令和本地评估报告路径见[后端说明](../README.md)。

### 验收与下一步

- 在 Windows 上通过本地前端构建、130 项后端测试、完整与演示数仓浏览器回归和 60 项接口冒烟。额外核对了有观测和缺测两种情况下的历史天气推理。浏览器回归启动方式见[前端说明](../../frontend/README.md#构建与验证)。
- 当前验证覆盖 Pandas、Parquet、SQLite 和 Chrome。Spark、MySQL、Redis、Docker 及公网并发仍需独立验收。
- 下一项模型实验是按计划起飞前 1 小时和 3 小时分别回放。按历史航班链的重建时间估算，约 53.2% 和 19.4% 的测试航班对应的前序航班可能已经到达。线上能否使用相关信息还取决于消息到达时间和机尾号调配。回放仅使用预测发出时已可得的特征，并与机场 × 时段历史延误率基线比较固定复核量下的命中数。后续再评估航司实时预计到达、机场拥堵和带发布时间的机场天气预报。

## 2026-11-17 验收记录

该轮依据开题报告检查后端，优先修复数据口径、时间泄漏、模型版本、缓存和后台作业中的缺陷。验证使用隔离数据库和数仓。

### 已完成的修改

| 范围 | 原问题 | 修改后的行为 |
| --- | --- | --- |
| 缓存 | 同 namespace 的 KPI、趋势等函数可能产生相同缓存键 | 缓存键包含函数完整名称，接口结果彼此隔离 |
| 数据库连接 | 请求结束后未移除线程级 Session | 应用上下文结束时回收 Session，释放事务与连接 |
| 后台作业 | 创建者的 ORM 对象跨线程使用，子阶段失败仍记成功 | 工作线程重新查询自身对象；嵌套失败向上汇总，下游停止；写库失败、线程启动失败释放锁 |
| 作业结果 | 序列化 JSON 被字符截断，耗时没有记录 | 保留完整 JSON，记录耗时；失败前 rollback 后重新落库 |
| 训练编排 | 接口 algo 未传给实际训练，批量预测可能使用旧线上模型 | 传递 algo，批量预测明确加载刚训练的版本；非二分类任务只评估，不冒充概率预测 |
| 模型版本 | 新训练直接修改全局截距和阈值；基线版本没有产物 | 各版本保存独立产物、阈值、截距和训练机场集合，候选训练不影响线上模型 |
| 版本标识 | 同秒训练可能版本冲突，预测版本名可与真实模型不符 | 版本时间包含微秒；预测版本来自实际加载产物 |
| 模型评估 | 时间切分可能拆开同一天；缺失标签被填成准点；单类 AUC 显示 0 | 按完整日期划分且至少三天；剔除无效标签；单类 AUC 为 null |
| 预测解释 | LightGBM 的解释基准用了线性基线截距 | 使用当前模型 SHAP bias，返回 base_logit 和贡献空间；明确百分点只是局部近似 |
| 泛化展示 | 用固定 0.5 阈值，并声称测试机场都未参加训练 | 使用对应预测版本阈值和训练机场集合；说明时间外推与机场留出实验不同 |
| 在线历史特征 | 总是读取最新一期，即使它晚于预测日期 | 仅统计预测日期之前七个自然日；前一日特征单独计算 |
| 离线历史特征 | 滚动七条观测日期当作七天；取消航班压低延误率；月初丢失上月历史 | 补齐自然日、按有效执行航班数加权，并读取上月最后七天 |
| 过站特征 | 用全月过站中位数和全月分位数，首航段也可能标记链可用 | 基准仅从先前样本估计，风险按低于历史基准判定；仅有效同机场衔接标记可用 |
| HHMM | 短值 9 被解析成 09:00；前 50 行兜底修正造成行位置差异 | 统一按 HHMM 左补零，9 表示 00:09；移除抽样改值；超过四位拒绝 |
| NOAA 气象 | 本地计划起飞时间直接匹配 UTC；跨年、凌晨窗口缺数据；0℃被替换；NaN 可进入分类转换 | 按机场 IANA 时区转 UTC，读取相邻年份；保留零值，过滤非有限值；未知时区与夏令时歧义标为不可用 |
| 气象窗口 | 最后一条观测之后的有效窗口未生成，天气类别只取前一小时 | 扩展末尾三小时，窗口天气类别取最大值；在线和离线使用相同方向的窗口 |
| 缺失数据 | 没有 ODS 气象时因 ApiError 缺少导入而不能走原文件回落 | 修复导入，允许按机场子集读取并验证真实 NOAA 站点文件 |
| 查询引擎 | 年分区整数过滤触发整表回退；回退重读可能丢失先前过滤；not in 被改成 in | 按字符串规范分区过滤；持续保留所有过滤条件；保留 not in 和空 in 语义 |
| 读取和写入 | limit 在全表加载后才应用；覆盖写先删旧数据 | Arrow 在读取时应用 head；pandas 先写临时目录再替换，失败保留旧分区；追加文件使用唯一名称 |
| Spark 写入 | 覆盖一个分区时存在影响其他分区的风险 | 写入明确的目标分区目录 |
| API 边界 | NaN、Infinity、小数可进入数值参数；日历非法日期可能变成 500 | 校验有限数和整数，验证真实日期、布尔值和正航程，错误返回统一 400/422 |
| 审计和导出 | 改密码请求体原样写入审计；导出先消耗整个生成器 | 审计仅记录修改字段名；CSV 有界读取并转义文本公式，保留数值负延误 |
| MySQL 和配置 | 特征名称串可能超过 VARCHAR(256)；默认数据源路径写死其他用户名 | 特征集改为 TEXT，提供升级 SQL；默认使用项目旁的数据源目录 |

### 验证结果

验证环境为 Windows，本次项目独立环境 `.venv` 使用 Python 3.12.14，Flask 3.1.3、pandas 2.3.3、NumPy 2.2.6、PyArrow 25.0.1、LightGBM 4.5.0、scikit-learn 1.5.2。

- `python -m pytest tests -q`：116 项通过，包含真实 LightGBM 和基线训练、产物加载、SHAP 概率重建、后台线程、覆盖写故障和输入边界测试。
- `python -m pip check`：无依赖冲突。
- `python -m compileall -q app scripts tests`：通过。
- 真实数据验证：2015-01、2015-02、2015-03 每月前 3,000 条 BTS 记录，合计 9,000 条；DFW、JFK、SFO 三个 NOAA 站点的 2015 年观测；OurAirports/OpenFlights/日历维表。
- 已跑通 ODS、DWD、DWS、ADS、LightGBM 训练、指定版本批量预测、模型激活和在线单航班预测，并检查四个主要读取接口。

机器可读结果在 `instance/verification/last_report.json`，过程日志在 `instance/pipeline-verification.log`。报告中的模型产物路径属于已经清理的临时目录，不能作为部署模型使用。样本模型仅用于验证实现，不用于证明最终预测精度。

### 复现方式

在 backend 目录打开 PowerShell。当前机器可直接使用已建好的独立环境，不必修改 Anaconda 或系统 Python。

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe scripts/verify_pipeline.py --rows 3000
```

新机器先创建虚拟环境，再安装完整建模依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-model.txt
```

基础 API 可只安装 requirements.txt。未安装 LightGBM 时对应回归测试会跳过，不能将其描述为完成了真实 LightGBM 验证。

### 使用原有数据时的升级

现有数据库和数仓未自动重写。时间解析、气象时区、过站基准和七日特征的口径已发生修正，旧特征与旧模型不能自动变成修复后的结果。

1. MySQL 旧实例按部署流程执行 `sql/migrations/20261117_model_features.sql`；新实例使用已更新的 `sql/mysql_schema.sql`。SQLite 对 TEXT 容量没有此限制。
2. 需要使用修正口径时，重新构建机场维表、对应月份 DWD/DWS/ADS，再训练候选模型；审核其日期切分和指标后，通过现有管理员上线接口切换。
3. 旧版本若没有有效产物，接口会拒绝上线；原先只有全局 calibration.json 的基线需重新训练，才能获得独立可复现版本。
4. 原数据源位置可通过 DATA_ROOT 覆盖，默认值为相对 backend 的 `../../航班延误预测数据源`。

### 验证范围与后续验收

开题报告指定 Python 3.10 / PySpark 3.4。本次机器上可用的独立验证环境为 Python 3.12，已完成 pandas 路径及真实 LightGBM 验证；没有将其描述为 Python 3.10 / PySpark 3.4 的部署验收。

Spark 适配目前仍通过 toPandas 将数据送入单机 ETL/服务。面对报告的约 6,300 万行规模，仍需把主要清洗、聚合和分页查询迁移到 Spark DataFrame/SQL，并在匹配的 Python/JDK 环境做全量压力测试。pandas 不是分布式计算的模拟实现。

本次 SQLite/内存缓存验证不替代实际 MySQL、Redis、Spark 联合部署测试。样本接口延迟不代表全量 P95 ≤3 秒，也没有执行外部 DeepSeek API 调用、全量下载/定时调度或中美跨域实验。回归/三级分类目前使用基线方法；在线分钟数和三级结果为概率映射及风险档位，应在论文和页面中据实说明。

目录替换和进程内锁保护同一服务进程的 pandas 读写；多进程或多节点部署仍需外部作业互斥与存储事务机制。

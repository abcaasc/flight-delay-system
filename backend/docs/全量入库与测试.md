# 全量接入与端到端验证

本次使用本地 MySQL 8.0 的 `flight_delay` 业务库，数据库密码只保存在被 Git 忽略的 `backend/.env` 中，服务和 CLI 日志对连接密码脱敏。原 SQLite 文件不删除。数据源为 `C:/Users/33753/Desktop/毕设/航班延误预测数据源`。

## 数据流和范围

- MySQL 保存用户、作业、文件清单、审计、模型版本等业务数据。
- Parquet 数仓保存航班明细、气象观测、特征、统计及批量预测。原始数据目录不修改、不删除。
- BTS 全部 120 个月，2015-01 至 2024-12，不设置 `limit` 或行数采样。
- NOAA 全部 1,142 个站点年度文件入 ODS；DWD 按可映射的机场站点聚合，未覆盖航班显式标为气象缺失。
- US Weather Events 压缩包按块流式读取，OurAirports/OpenFlights 构建维表。
- IEM 和 STPN 按既有设计作为本地交叉验证/跨域数据源直读，登记清单和校验信息；不凭空创建缺乏字段契约的 MySQL 大表。
- 所有已登记输入文件写入 `source-catalog.json`，原清单对账见 `source-verification.json`。清单自身无法预先记录自身最终哈希，单独列为无清单基准文件。

## 运行与恢复

```powershell
cd backend
.\.venv\Scripts\python.exe scripts/full_pipeline.py --status
```

当前步骤和断点在 `instance/full_pipeline/report.json`，每步详细结果在同目录的 `steps` 子目录。完整运行包括 625 步：源校验、维表、全部 ODS、按年气象/按月 DWD-DWS-ADS、模型训练、120 个月预测及最终验收。`pipeline.log` 为作业日志，`pipeline.err.log` 记录异常。

任务在后台运行时，不要另开相同导入作业。若任务已经失败或电脑重启，再运行下面命令，会跳过已经成功的步骤并从失败处恢复：

```powershell
.\.venv\Scripts\python.exe -u scripts/full_pipeline.py
```

重试 ISD 年分区或气象批次会先覆盖第一批再追加后续批次，避免重复；单月表原子覆盖其对应分区。流程校验嵌套失败和文件死信，不把部分成功当作全量完成。磁盘剩余不足 10 GiB 时停止并保留断点。

## 验证口径

`verify_full_month.py` 在当前开发库中先验证 2015-01 的完整月份，用于提早发现全尺寸内存、清洗、聚合和建模问题。它不是十年全部完成的证明；报告是 `full-month-pilot.json`。

十年入库不采样。正式全流程模型验收使用最近三个完整月份的全部有效样本，按日期切分训练、验证、测试，保证日期不交叉；然后对 120 个月逐月生成回溯评分。模型性能仅报告独立测试集，历史回溯评分不作为时间外推性能证明。

目前实际 ETL 使用 pandas/pyarrow 按月、气象按小批次运行；未安装 PySpark，不能将本次运行宣称为 Spark 分布式性能验收。训练只读取白名单数值特征及标签，气象众数用向量化计数，减少 16GB 内存机器上的峰值占用。

最终验收核对 120 个月分区及明细/特征/预测行数一致，调用首期、中间期、末期接口、STPN 跨域接口，以及实际 MySQL 服务的接口冒烟和 Chrome 浏览器回归。报告 `validate.json` 和 `report.json` 的 `status=success` 才代表整条流程完成；`running` 仅代表仍在处理中。

## 启动服务

```powershell
cd backend
.\.venv\Scripts\python.exe -m waitress --listen=127.0.0.1:5000 run:app
```

前端仍按 `frontend/README.md` 启动。服务是独立进程，长时间任务不依赖聊天窗口持续打开；电脑关机/休眠会使处理停止或挂起，需要保持设备运行。

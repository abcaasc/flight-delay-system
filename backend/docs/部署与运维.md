# 部署与运维手册

## 一、单机开发（默认，零外部依赖）

```powershell
cd backend
pip install -r requirements.txt
python -m flask --app run.py init-db
python -m flask --app run.py seed-users
python run.py            # http://127.0.0.1:5000
```

默认行为：

| 项 | 默认值 | 说明 |
| --- | --- | --- |
| 数据库 | `instance/flight_delay.db`（SQLite） | 未配置 `DATABASE_URL` 时 |
| 缓存 | 进程内 TTL 缓存 | 未配置 `REDIS_URL` 或连不上时 |
| 计算引擎 | pandas（pyarrow 分区裁剪） | 未安装 pyspark 或 JDK 版本不匹配时 |
| 预测 | LightGBM（若装了），否则内置线性基线 | 看 `GET /api/v1/system/health` 的 `engine` |

## 二、切到 MySQL 8.0

```sql
CREATE DATABASE flight_delay DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER 'fds'@'%' IDENTIFIED BY 'strong-password';
GRANT ALL PRIVILEGES ON flight_delay.* TO 'fds'@'%';
FLUSH PRIVILEGES;
```

```dotenv
DATABASE_URL=mysql+pymysql://fds:strong-password@127.0.0.1:3306/flight_delay?charset=utf8mb4
```

```powershell
python -m flask --app run.py init-db     # ORM 建表（13 张业务表）
```

建库脚本见 `sql/mysql_schema.sql`（可选的纯 SQL 版本，便于在论文里展示 E-R 与 DDL）。

## 三、切到 Redis 缓存

```dotenv
REDIS_URL=redis://127.0.0.1:6379/0
CACHE_TTL_DASHBOARD=600
CACHE_TTL_QUERY=300
```

验证：`GET /api/v1/system/health` 的 `cache.backend` 应为 `redis`；`POST /api/v1/system/cache/flush` 可手动清空看板缓存（ETL 完成后会自动清）。

## 四、切到 Spark

前置条件：**JDK 11 或 17**（PySpark 3.4 不支持 JDK 21）、`pip install pyspark==3.4.4`。

```powershell
$env:JAVA_HOME = "D:\tools\jdk-17"
$env:QUERY_ENGINE = "spark"
$env:SPARK_MASTER = "local[6]"
python -m flask --app run.py doctor
```

Spark 参数（`app/services/spark_session.py`，与设计说明书 §4.1 一致）：

| 参数 | 取值 | 理由 |
| --- | --- | --- |
| `spark.master` | `local[6]` | 8 核留 2 核给 OS 与前端 |
| `spark.driver.memory` | `2g` | 单机 driver 不宜过大 |
| `spark.executor.memory` | `4g` | 受容器限制 |
| `spark.sql.shuffle.partitions` | `64` | 核数 × 8–10，避免 200 个空任务 |
| `spark.sql.adaptive.enabled` | `true` | AQE 合并小分区 |
| `spark.sql.adaptive.skewJoin.enabled` | `true` | 热门机场（ATL/ORD）倾斜 |
| `spark.sql.autoBroadcastJoinThreshold` | `30MB` | 维表广播 |
| `spark.sql.sources.partitionOverwriteMode` | `dynamic` | **幂等关键**：只覆盖命中分区 |

> 两种引擎读同一套 Parquet，可**不改代码**做加速比对照实验：
> 同一接口分别用 `QUERY_ENGINE=pandas` 与 `spark` 跑，记录 `X-Response-Time-Ms` 响应头即可。

## 五、生产部署

```powershell
pip install waitress
waitress-serve --listen=0.0.0.0:5000 --threads=8 run:app
```

访问控制与反代要点：

| 项 | 建议 |
| --- | --- |
| `SECRET_KEY` / `JWT_SECRET` | 必须改成长随机串（≥32 字节） |
| 反向代理 | Nginx `client_max_body_size 60m`（staging 上限 50 MB） |
| HTTPS | 生产必须开；JWT 走 Header，不放 URL（导出链接除外：`?token=`） |
| 进程数 | 单进程多线程（作业锁为进程内锁）；多进程需把锁换成 Redis 锁 |
| 日志 | `instance/backend.log`（20 MB × 5 轮转） |

## 六、月度增量 SOP（约 3 分钟）

1. 把新月份的 BTS 包放进 `01_BTS航班准点数据/`；
2. 页面或 CLI 先校验：`flask --app run.py verify --dataset bts`；
3. 入湖：`flask --app run.py ingest --dataset bts --periods 2025-01 --mode incremental`；
4. 加工：`flask --app run.py etl --periods 2025-01`；
5. 训练与预测：`flask --app run.py train --periods 2024-11,2024-12,2025-01 --online`；
6. 核对：`GET /api/v1/quality/report?period=2025-01` 看 `rows.kept_rate` 与 `drop_reasons`。

## 七、补数与回滚

| 场景 | 操作 |
| --- | --- |
| 某月数据有误 | `--mode full` 重跑该月（分区级覆盖，不影响其他月份） |
| 某文件损坏 | 重新下载该文件 → `verify` 通过 → 重跑该月 |
| 误删分区 | 从 raw 区（`data/raw/` 或原始数据源目录）重跑，无需重新下载 |
| 模型效果回退 | `POST /api/v1/model/online` 指定旧版本（admin） |
| 缓存脏读 | `POST /api/v1/system/cache/flush` |

## 八、巡检（每周 5 分钟）

| 检查项 | 阈值 | 动作 |
| --- | --- | --- |
| 死信表新增 | > 0 | `GET /api/v1/ingest/failed` 逐条处理 |
| 分区文件数 | > 20 | 触发合并（`target_files` 调小后重跑该月） |
| 月环比行数波动 | > 30% | 人工确认是否上游变更 |
| 重复率 | > 0.5% | 检查去重规则 |
| 作业成功率 | < 95% | `GET /api/v1/system/job/stats` 定位慢/败任务 |
| 数据新鲜度 | 超过 26 小时标黄 | `GET /api/v1/system/freshness` |

## 九、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `flask: command not found` | 未装依赖 | `pip install -r requirements.txt` |
| `未找到任何源文件` | `DATA_ROOT` 指向不对 | 改 `.env` 的 `DATA_ROOT`，或 `flask data-scan` 核对 |
| `数据尚未就绪（521）` | 数仓为空 | 先跑 `pipeline` 或对应 `etl --table` |
| Spark 初始化失败 | JDK 21 / 未装 pyspark | 装 JDK 17 并设 `JAVA_HOME`；不影响 pandas 引擎 |
| 概率全是 0/1 | 用了 `predict()` 而非 `predict_proba()` | 本项目已修复（见测试用例 D-10） |
| 机场无气象 | 该年无对应 ISD 站点文件 | 属正常，`weather_available=0`，模型可处理缺失 |
| 导出被截断 | 默认上限 1000 行 | 收窄筛选条件；上限由 `EXPORT_MAX_ROWS` 控制 |
| AI 助手 `degraded=true` | 未配 `DEEPSEEK_API_KEY` | 配置后自动切真实模型，失败仍降级 |
